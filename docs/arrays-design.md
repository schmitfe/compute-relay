# Native Slurm arrays: proposed optional extension

Status: planned and unsupported. Ordinary broker jobs remain single-node, single-allocation jobs. The workflow extension can create ordinary independent jobs; it does not turn them into a native array. Do not enable native submission until the accounting and identity gates below are implemented and accepted against the disposable Slurm fixture.

## Initial scope and public contract

Add a default-disabled `arrays` extension with its own models, migrations, views, MCP tools, rendering, backend adapter and fixed remote source. A human project policy enables arrays and limits element count and concurrency. An agent needs `arrays:submit` plus ordinary job scopes. Start with one homogeneous Python/Bash package, one existing permitted environment/cluster, a bounded explicit sorted list of unique nonnegative indices (at most 100 initially), and a concurrency integer from 1 through element count. Each element uses the same bounded single-node resources. No arbitrary array expression, scheduler directives, per-element resource edits, requeue, subset retry, dependency strings or heterogeneous allocation.

Suggested routes are project `/arrays` create/list, array `/{id}/prepare`, `/{id}/execution-requests`, `/{id}` status, `/{id}/tasks` bounded page, and whole-run cancellation through its ordinary Attempt. A task maps its index to one immutable parameter row from a hashed JSON file. Each task validates `SLURM_ARRAY_TASK_ID` against this list on compute and runs in its own service-derived task directory. Review binds every index, parameter digest, per-task resources, concurrency, generated script and total reservation. Human rejection consumes no submission units.

`ArraySpec` records the immutable normalized specification and core Job. `ArrayRun` binds one core Attempt and the exact expected index set. `ArrayTask` has a unique `(run, index)` constraint, native identity, state and final accounting evidence; it does not independently submit. A fresh array run, including a failed-element retry, requires a fresh approval/admission and reservation. The first implementation cancels the whole array only.

Slurm identifies elements using both the parent array ID and task index; raw child job IDs and execution order are not stable substitutes. `%A` and `%a` support separate task log names, while `squeue --array` expands compressed queue rows. The concurrency `%N` limit restricts simultaneous running elements; each element still counts as a regular Slurm job. [Slurm job-array documentation](https://slurm.schedmd.com/job_array.html), [squeue documentation](https://slurm.schedmd.com/squeue.html).

## Required core accounting hooks

The existing `Attempt.objects.count()` lifetime limit and single-allocation parser cannot safely admit arrays. These are blockers, not extension-only details that can be hidden in an extra JSON field.

1. Persist a generic immutable `Attempt.admission_units` integer, default 1. At admission, obtain a strictly bounded unit count from a prepared extension descriptor: `N` for an array. Check and consume `N` units atomically under the existing project/grant lock. Sum persisted units across **all** project attempts for lifetime admission and across unsettled/nonterminal attempts for the active-job limit, including when an extension is disabled or uninstalled. Cancellation, failure and settlement do not refund lifetime units. Conservatively count all queued array elements against active capacity, regardless of `%N`. Ordinary jobs and arrays compete for the same caps.
2. Add a narrow preparation hook that can contribute a schema-validated descriptor, generated files and reservation multiplier before canonical hashing. Keep `maximum_allocation` and project per-job checks expressed **per element**; reserve `N × effective per-element CPUs/GPUs × requested walltime`. Do not multiply only by concurrency. Bound all arithmetic and keep the descriptor/helper source digest inside the reviewed package.
3. Add a trusted worker backend-adapter selection hook after core package and connection verification. It may replace the backend with an extension adapter exposing the existing submit/reconcile/observe/cancel/collect interface. Core must retain online dispatch, durable intent, generation fencing, idempotent reporting and ledger settlement. The extension cannot create its own unmetered scheduler channel or accept agent-supplied Python import paths/source.
4. Permit an explicit registered extension identifier in the prepared schema/registry. Disabled-extension admission and first-dispatch fencing remain mandatory; already dispatched arrays retain monitoring and final settlement even while new array use is disabled. This requires installed monitoring code, or a generic persisted operation/version resolver; disabling configuration must not erase the decoder for outstanding attempts.

An alternative is a core Attempt per element, but the current one-to-one ExecutionRequest/Attempt model, single online-dispatch authority and parent submission journal would need a larger redesign. One aggregate Attempt with persisted weighted admission and durable per-element evidence is the smaller coherent first implementation.

## Submission, identity and finality

Submit the exact prepared batch script once with a service-generated `--array=<bounded indices>%<concurrency>` and the broker attempt marker. Journal the parent intent before `sbatch`; a transport/RPC/nonzero response remains `submission_uncertain`. Reconciliation uses the original attempt marker, bounded submission window, own UID and the entire expected array identity. Never infer nonacceptance from missing queue/accounting rows or resubmit a partially visible array.

The extension's one-shot remote operations must use the same reviewed no-follow staging and bounded subprocess principles as core SSH, without an arbitrary command endpoint. Each task identity binds cluster, parent array ID, task index, attempt marker, submission window and expected task work directory. Cancellation revalidates the live parent/task membership before targeting the whole managed array. A parent numeric ID alone is insufficient after ID reuse.

Observe queue state in one bounded expanded query, then obtain allocation records with `sacct --array --allocations --duplicates`, explicit fields and a bounded time/own-user filter. Parse the displayed array element identity deliberately; do not assume `JobIDRaw` equals `parent_index`. Reject unexpected indices, truncated/range rows, contradictory duplicates and native requeues. Ignore `.batch`, `.extern` and step rows. Retain the core minimum-one-second meter for each allocated element. [sacct documentation](https://slurm.schedmd.com/sacct.html).

Only declare aggregate final accounting after **every expected element** has one unambiguous terminal allocation record with a real end timestamp and validated resources/identity. Sum CPU/GPU resource seconds once per element, including failed/cancelled elements. The parent placeholder must neither be omitted when it is an actual element nor charged again as a separate allocation. Parent completion, queue disappearance, partial accounting or zero-use missing elements never release the full reservation. Duplicate/requeue evidence requires operator resolution in this first version. Actual observed allocated runtime is charged in full even beyond the reservation; debt blocks new admissions without changing the project's explicit pause setting.

Logs and artifacts are bounded per task and aggregate. Use service-derived task prefixes in declared paths; no glob or arbitrary filesystem traversal. First acceptance can collect a fixed JSON result per element under the aggregate report limit; large result datasets should remain digest-bound remote references through separately enabled storage/transfer policies. Whole-array cancellation acknowledgement is not accounting finality.

## Acceptance gates

Pure tests must cover canonical index validation, overflow-safe reservation, no free slots from throttling, rendering/file names, compressed rows, non-monotonic raw IDs, exact child identities, missing/duplicate/unexpected children, minimum-second accounting, parent placeholder handling and bounded collection. Transactional tests must race an array and an ordinary job for the last lifetime/active slots, rotate multiple keys, reject stale human approvals and preserve cap usage when the extension is disabled.

The disposable native fixture must submit a tiny three-element array, recover a lost parent reply without resubmission, observe partial completion while keeping funds reserved, collect distinct task outputs, settle exact child sums once, and cancel an array containing both pending/running elements. Add job-ID reuse, comment mismatch, scheduler requeue, accounting lag and controller outage tests. No institutional submission is required for this implementation gate. Until all these paths pass, the product should continue reporting native arrays as unavailable.
