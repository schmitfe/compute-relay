# Open work

This is the single backlog of accepted work and deliberately deferred
capabilities. P1/P2 items are accepted; P3 items need concrete user or site
demand before they become commitments. Importance reflects user risk and
release readiness, not convenience.

| Priority | Work | Why it matters / completion gate |
| --- | --- | --- |
| **P1 — release gate** | Publish a verified private security-reporting channel, supported-version policy and response ownership. | `SECURITY.md` currently describes fallback reporting. Do this before claiming release support. |
| **P1 — deployment evidence** | Run and record acceptance on each supported target class, including a permitted real Slurm site. | Synthetic tests do not prove site-specific authentication, accounting, software availability or filesystem behavior. Follow [testing guidance](testing.md#real-cluster-acceptance). |
| **P1 — local service responsiveness** | Capture and diagnose a recurrence of the unresponsive portal observed during real-cluster job preparation, then add a regression test for the proven cause. | The stall lasted at least four minutes and queued 24 requests; restarting restored access. Synthetic concurrent preparation, receipt pruning, cold imports, slow artifact readers and abandoned requests did not reproduce it. On-demand private all-thread stack capture is available; see [diagnostics and measured probe scope](runtime.md#diagnosing-an-unresponsive-portal). Keep this open until the cause is established and concurrent API/portal recovery is verified. |
| **P2 — storage integration** | Advertise protected storage roots from the worker and connect estimates to the actual write target before claiming storage reservations. Add site-specific quota reporting only where required. | Current free-space reports are advisory and native user quotas remain unknown. Never attribute environment-build bytes to a different selected target. See [storage limits](extensions-storage.md). |
| **P2 — artifact and environment retention** | Define local and remote retention, preview reclaimable bytes and add bounded cleanup of expired, unreferenced artifacts, partial transfers, attempt directories and managed environments. | Preserve active or uncertain attempts, pending collection, pinned results and references from jobs, environments and workflows. Verify ownership and protected roots; never follow links or remove shared inputs still in use. Keep accounting and required receipts, and make interrupted cleanup resumable. Include storage-target accounting before automated deletion or migration. See [environment limits](environment-builds.md#storage-retention-and-current-limits). |
| **P2 — admission bursts and outstanding work** | Allow bursts of hundreds of submissions while bounding sustained request rates and outstanding draft/prepared, review and queued/running work. Make current capacity and retry timing visible. | Project/key rate controls must share an installation bound; more keys must not bypass project limits. Keep lifetime spending/submission policy separate from traffic and backlog controls. The current 1,000 charged-job-record cap also counts completed jobs until archival, independently of a 10,000-submission grant; expose and resolve that mismatch. Stable idempotent retries must not consume capacity twice; closeout must release outstanding-work capacity without deleting accounting history. Test large bursts and sustained overload without flooding Slurm or accumulating tens of thousands of prepared jobs. |
| **P2 — collection load acceptance and quota diagnostics** | Verify serialized output publication and bounded contention retries on the next permitted real-site load run, and report which storage quota is exhausted with current usage and headroom. | Output requests share a worker-owned FIFO async lock; per-request retries preserve unchanged descriptor/chunk replay, bounded backoff, lease renewal, cancellation and authority loss. Sustained contention from independent writers still has finite recovery. The cluster run exhausted the former 1,000-object limit after 476 admitted jobs at only 506 KiB and reached the 32 MiB logical-metadata ceiling after 788 admissions. Scripts, outputs and retained request history consume separate quotas independently of the submission allowance. Surface byte, object, metadata and incomplete-transfer limits before admitting work that cannot fit; integrity/authority failures must remain failures. |
| **P3 — investigation guidance** | Add explainable local/cluster placement, enforceable investigation sub-budgets, richer rate-limited progress and further summary pagination only if users need them. | Placement and investigation allowances must share current authority and reservation rules. Existing waits, closeout and bounded summaries remain the supported behavior. See [workflow design](portable-compute-workflow.md). |
| **P3 — only on demand** | Add other environment managers/languages, native Slurm arrays, alternative schedulers, remote HTTP MCP/OAuth clients, generated OpenAPI/admin APIs, large-data transfer, packed environments, or direct/object-store artifact delivery. | These expand supported contracts and security surface. Implement only for a concrete user/site need, with separate authorization, accounting and acceptance criteria. Current limits are in [runtime](runtime.md), [backends](backends.md) and [module guides](extensions.md). |
